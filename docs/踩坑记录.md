## 案例一：光强读数永远只有 0 和 255

**现象**

调试光强检测时，采到的数值只有 0 和 255 两个极端值，中间没有任何过渡。拿东西遮挡光敏电阻，也看不到数值连续变化。

**第一反应**

先怀疑是采样程序写错了：查过采样时序，换过采样通道，也调过减速计数的时间，读数还是只有那两个值。

**排查过程**

后来回到器件本身去看电路：老师给的 LM393 不是 ADC，它是一片电压比较器。IN+ 接的是 R1 10kΩ 与光敏电阻的分压点，IN- 接电位器 PR1 设定的参考电压，输出只有高、低两种状态。当时查的很多教程都要求配一片 ADC 芯片（比如 ADC0832）才能拿到具体 AD 值，才会让人误以为读数该是连续的。

**定位**

真正的原因：LM393 是电压比较器而不是模数转换器，它的输出本来就是开关量。程序里那个 0/255，只是把高低电平读成了一个字节的两个极值，不是采样出了问题。

**解决**

不再指望它给出连续光强值，改成直接拿这个开关量做阈值判断：比较器输出有效就点亮车灯 LED，无效就熄灭。阈值靠电位器 PR1 手调，想改亮暗门限直接拧电位器，不动代码。

**这次学到**

写驱动之前先确认器件的输出类型。读数不对，先怀疑器件性质，再怀疑程序。

## 案例二：四个任务抢占一个主循环

**背景**

这个系统同时要管四件事：按键扫描、数码管显示、光强采样、OLED 刷新。四件事需要的频率完全不同，按键要快，OLED 一秒刷一次就够。最直接的想法，是在主循环里用延时把它们依次错开。

**问题**

用延时错开，等于一个任务执行的时候别的任务只能干等。延时给得越保守，一轮循环越长，按键这种要求快的任务就被拖住了。

**做法**

把数码管扫描放进 1ms 的定时器中断，中断里只做最要紧的一点点事；其余任务各配一个软件计数器，在主循环里跑到自己的计数值才执行一次。用计数减速代替长延时，任务之间谁也不等谁。

**代价**

每个任务的执行频率变成由计数器的分频值决定，改频率要回头改计数器的门限值，不如直接写延时直观；计数器变量也得多开几个。

**这次学到**

实时系统里任务的节奏应该由统一的定时基准来划分，而不是互相用延时排队。

## 案例三：OLED 显示时间不知道怎么下手

**解决方式**

当时没吃透 OLED 显示实时时间的原理，就直接换方案：时间用数码管显示，另外单开一个显示模式，避免和时间设置、光强值显示互相冲突。按下按键在几个模式之间切换，设置时间时被调整的那一位闪烁提示。

**这次学到**

不会做就先绕开，用一个自己能讲清楚的方案达到同样的功能，比硬啃一个不懂的模块更划算。
